# 复现与迁移清单

本仓库包含脱敏案例总结及允许公开的实际执行代码，仍需接入自己的数据库、原富文本渲染器和本地工具。完整部署步骤见 [deployment.md](deployment.md)；以下保留原实验复现口径。

## 依赖边界

- 可交互且已解锁的 Windows 会话、已登录的目标应用。
- Windows-MCP 或该项目同源构建的 wincli；固定版本并验证其当前参数和坐标系。
- 本地执行程序、富文本剪贴板写入器、版本事件存储。
- 有权限使用的 Jev 服务。实测接口为 `https://api.typesafe.ai/v1/systemone`，模型 `jev-1.13.0`；后续版本应另行验证。

## 接入步骤

1. 把实际业务事件转换成来源、记录 ID、版本摘要、更新时间和文件位置；先读现有数据作为基线，不能把所有历史数据当新上传。
2. 用本地轻量监听发现变更；只有可处理的新事件才启动模型与桌面执行。
3. 在导航前并行准备剪贴板，派发粘贴前再验证来源版本、格式和剪贴板状态。
4. 使用 [decision-contract.json](../examples/decision-contract.json) 作为有限动作定义参考；为自己的业务重写状态，不发送整份正文。
5. 每个阶段先定义本地前置条件和成功信号，再执行一次动作。控件不唯一、页面未出现或动作结果未知时停止。
6. 分别验证“已有正确时间”“空白时间”“错误日期”“弹窗正确但表单未生效”。不能仅测试默认值恰好正确的路径。
7. 保存前记录授权和派发状态；成功必须以业务回执为准，失败不能重复点击保存。
8. 先做无保存测试，再做明确授权的单次保存测试，最后评估持续运行策略。

## 请求结构示例

```json
{
  "model": "jev-1.13.0",
  "state": "正文粘贴已确认，底部定时区域尚不可见，只需滚动页面。",
  "questions": {
    "next": {
      "type": "choice",
      "instructions": "仅选择当前阶段允许的动作。已经粘贴不得再次粘贴。",
      "criteria": {
        "scroll_page": "粘贴已确认且底部不可见，只滚动编辑器外侧页面。",
        "stop_unknown": "先前动作结果未知，停止，不重放。",
        "stop_ambiguous": "目标不能唯一识别，停止。"
      }
    }
  }
}
```

它只是示例。实际成功运行使用本仓库记录的六项动作集合；精简集合后的延迟或准确率没有在这里验证。完整动作执行仍由本地程序负责。

密钥从本机凭据存储或进程环境读取；本地实现采用当前 Windows 用户的 DPAPI 加密存储。加密文件也不上传，日志不保存 Authorization 请求头。
