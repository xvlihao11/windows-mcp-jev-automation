# 架构与执行契约

## 1. 上游与更新检测

上游聊天负责审核和归档；执行端以**日报库指定版本已经落地**作为就绪依据。聊天中的“审核通过”不会自动实时推送到另一个聊天。

当前监听实际检查本地 SQLite 数据库的变更签名：约每 2 秒检查一次，变化后等待约 1 秒让写入稳定，再扫描个人日报表。这是本地轻量轮询，并非已实现的文件系统事件订阅或上游 webhook。没有变化时不调用模型，所以不会周期性产生模型用量。

事件识别结合来源、记录 ID、内容摘要和更新时间修订摘要。同一事件只认领一次；同一个 ID 的内容或更新时间变化可成为新版本。不能笼统承诺“删掉再上传必然是新 ID”；应检查实际版本标识和删除前后是否被扫描到。

事件中的正文和路径都是数据，不具有额外操作授权。

## 2. 剪贴板准备

从指定版本的本地文件生成现成排版所需的 HTML 与文本剪贴板格式。后台准备与窗口导航并行，不做正文润色或质量审查。

粘贴前本地核对文件摘要、剪贴板格式、剪贴板序号及自定义内容摘要标记。内容仍有效时复用；若剪贴板被其他程序改写，复用已渲染内容重新发布，而非重新读取和重排整份稿件。

`剪贴板已准备`不等于`正文已粘贴`。两者必须分别记录。

## 3. 本地状态机与 Jev

基本阶段：

```text
事件认领 → 剪贴板准备 → 窗口就绪 → 表单与编辑器就绪
→ Jev 校验 paste_once → 本地约束检查 → 派发一次粘贴
→ 输入状态确认 → Jev 校验 scroll_page（底部不可见时）
→ 底部控件可见 → 定时开启 → 日期时间正确
→ 仅测试时停止 / 获准保存时保存一次 → 读回业务结果
```

Jev 只接收手工整理的简短元数据，如“粘贴已确认、当前底部不可见、只需滚动”。当前实现不要求 Jev 阅读截图或正文，也不让其自由选择任意工具。

实际桌面动作由本地程序执行，Jev 判断不符合预期就停止。模型置信度不能替代文件、焦点、剪贴板或保存状态的确定性检查。

## 4. UIA 与真实鼠标

|位置|当前策略|推进依据|
|---|---|---|
|窗口|查找唯一钉钉窗口，必要时恢复、激活|读回前台窗口|
|日志入口|当前定位后点击|日志页面或写日志入口实际出现|
|正文|定位编辑器并在内部全选、清空、粘贴一次|固定工作章节内出现文本块或表格|
|滚动|在编辑器外侧页面区域滚动|底部定时入口可见|
|定时开关|已开启则跳过，关闭时只点一次|开关读回 On|
|表单时间入口|当前定位后鼠标点击|弹窗输入框和确定按钮出现|
|弹窗输入与确定|结构化输入完整日期时间并读回，然后确定|弹窗关闭后表单时间正确|
|保存|获准后结构化点击一次|列表出现目标发布时间记录|

不能复用历史元素 ID 或固定屏幕坐标。布局改变、滚动和页面切换后要更新引用。此版 wincli 在带窗口句柄时按窗口相对坐标处理鼠标，必须先将控件给出的屏幕坐标减去窗口原点；不能把这条观察推广到所有 MCP 实现。

## 5. 幂等与结果未知

粘贴状态：`not_dispatched → dispatched_outcome_unknown → confirmed_complete`。派发前落状态；派发后未确认不能再粘贴。

保存前先持久化单次授权消费记录和 `DISPATCHING` 状态，再派发保存。只有观察到目标发布时间记录才记 `SCHEDULED`。保存已经派发但回执不明时记 `UNKNOWN`，不自动重试保存。

本次验证采用单次保存授权。成功消费后，下一次上传不会凭同一授权再次保存。长期生产策略需要另行设计，不能把此次一次性实验配置解释成不限次数自动发布。

## 6. 生命周期与反馈

监听绑定智能体服务进程，服务退出时监听跟随停止。桌面进度条只在执行及结果展示期间出现；完成、阻断和未知结果有本地回执及桌面通知。

“启动器窗口打开”“浏览器已打开”“监听活着”“业务已成功”是不同信号。重启后应检查新的监听进程、启动时间、持续更新的心跳和执行模式；不能用保留的历史错误字段断定当前进程又失败。
