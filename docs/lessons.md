# 踩坑、修复与待办

## 已处理的问题

1. **复制、粘贴、滚动语义混淆。** 分成三个动作；已经粘贴就不能再选择粘贴。派发结果未知时停止，不能用重试来探测。
2. **剪贴板准备滞后。** 改成直接从文件准备，与窗口导航并行；模型不再负责决定剪贴板是否真的就绪。
3. **富文本 Edit 的 value 为空。** 钉钉可能把文本或表格暴露为兄弟控件。改为在固定工作章节范围内确认非空，不能拿其他栏目内容冒充粘贴成功。
4. **UIA 找到控件但点击不导航。** 读回页面是否变化；为已观察到的失效入口选用当前定位坐标点击，不把“请求已发出”当成导航成功。
5. **隐藏复选框为零坐标。** 配对当前唯一可见标签的位置，并在点击后核实开关状态；已经开启就不重复切换。
6. **输入框重名。** 表单和时间弹窗都叫“选择发送时间”。保留当前表单引用，弹窗只允许唯一的其他候选，并要求确定按钮同时存在。
7. **时间默认值掩盖漏实现。** 早期只检查 23:30，缺少空白或错误时输入的分支。现已实现：打开时间框 → 输入完整日期时间 → 弹窗读回 → 确定 → 表单再次读回。
8. **弹窗正确不等于表单生效。** 曾出现弹窗读回正确、确定后表单仍旧的情况。因此保留表单二次确认。
9. **坐标系混用。** 本版 wincli 的带窗口鼠标参数按窗口相对坐标处理，控件快照给出屏幕坐标；转换错误曾导致点到其他窗口。先核实前台窗口和边界，再转换。
10. **启动器提示误导。** 服务已在后台运行时，启动器只打开浏览器便退出，外层仍打印“Service stopped”。这样的窗口没有控制后台服务，Ctrl+C 无法停止它。恢复由前台启动器拥有服务之后，Ctrl+C 才能控制服务；后台监听继续跟随服务生命周期。

## 已知未完成项

- Jev 查询目前只对 HTTP 503 有一次有限重试。SSL EOF、连接中断等异常仍会停止流程，不能宣称所有网络故障均已自动恢复。
- 需要为只读判断请求设计总时限和有限重试；不能因此重放已经派发的桌面动作，不能关闭证书校验。
- 状态文件保留了历史 `last_result`、`error`，新启动时可能继续显示旧告警，应把当前健康与历史结果分开。
- 全窗口快照占主要耗时，应评估父容器范围查找、单控件读回和复用同次观察，保留必要的日期和保存确认。
- 单次保存授权用于本次实验。正式持续运行需要清晰的日级策略、版本策略与异常恢复方式。
- 上游到本地的真实推送尚未取代当前数据库轻量轮询。

## 后续实验顺序

1. 固定同一输入，重复测量完整流程并记录缓存是否命中。
2. 优先减少快照范围与冗余次数，分别记录主模型、Jev、工具和页面等待耗时。
3. 增加受控断线测试：判断请求可重试，粘贴和保存不可盲目重试。
4. 设计纯状态机与 Jev 阶段校验的同条件对照。
5. 再迁移到新业务；不要把日报案例的动作标签直接当成答题策略。
